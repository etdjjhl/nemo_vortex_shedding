# 涡激振荡流场代理模型 —— 项目汇报

---

## 一、系统描述

### 物理背景

本项目模拟的是**二维（2D）不可压缩粘性流体绕圆柱流动**的问题，即经典的"涡激振荡"（Vortex Shedding）现象。当流体以一定速度流过圆柱时，圆柱两侧会交替产生旋转方向相反的涡旋，形成周期性的卡门涡街（Kármán Vortex Street）。

### 计算域

| 参数 | 值 |
|------|----|
| 域形状 | 矩形通道 |
| 域尺寸 | 1.60 m × 0.41 m |
| 维度 | 二维（2D） |
| 仿真软件 | COMSOL Multiphysics |
| 时间步长 | 0.01 s/步 |
| 每条轨迹时长 | 600 步（共 6 秒） |

计算域为一个水平矩形通道，圆柱置于通道内部。流体从左端（入口）以给定速度流入，从右端（出口）流出，上下为固壁边界，圆柱表面为无滑移壁面。

```
  ┌────────────────────────────────┐
  │ →→→              ○  (cylinder) │
  │ →→→  (fluid)                  │
  └────────────────────────────────┘
  inflow                      outflow
         1.60 m × 0.41 m
```

### 网格

流场被离散成**非结构三角形网格**（Unstructured Triangular Mesh）。每个样本的网格节点数约为 1,700–2,100 个（因圆柱大小不同而略有差异），三角形单元约 3,600 个，边（Edge）约 11,000 条。

## 二、训练数据介绍

### 数据来源

数据集来源于 DeepMind 发布的 MeshGraphNet 标准测试集（cylinder flow），由 COMSOL 仿真生成，以 TFRecord 格式存储。

### 数据规模

| 数据集分区 | 样本数 | 用途 |
|-----------|--------|------|
| train     | 1,000 | 训练 |
| valid     | 100   | 验证 |
| test      | 100   | 推理评估 |

### 每个样本的内容

每个样本代表一个**独立的仿真场景**，包含：

| 字段 | 含义 | 形状 |
|------|------|------|
| `mesh_pos` | 网格节点的 (x, y) 坐标 | [N, 2]，N ≈ 1,900 |
| `cells` | 三角形单元顶点索引 | [E, 3]，E ≈ 3,600 |
| `node_type` | 节点类型标签 | [N, 1] |
| `velocity` | 每个时间步每个节点的速度 (u, v) | [600, N, 2] |
| `pressure` | 每个时间步每个节点的压力 p | [600, N, 1] |

**节点类型分布（以某典型样本为例）：**

| 类型 | 含义 | 数量（典型值） |
|------|------|---------------|
| 0 — Normal | 流场内部节点 | 1,689 |
| 1 — Inflow | 入口边界节点 | 17 |
| 2 — Outflow | 出口边界节点 | 17 |
| 3 — Wall | 圆柱表面 + 通道壁面节点 | ~200 |

**数据量估算：**  
单个样本约含 1,900 节点 × 600 时间步 × 3 个物理量（u, v, p），本次训练使用其中前 300 步，相当于每个样本提供约 57 万个节点时间步数据点。

## 三、网络结构介绍

### 模型：MeshGraphNet（MGN）

本项目使用的模型是 **MeshGraphNet**，由 NVIDIA PhysicsNeMo 框架提供。其核心思想是将物理场的网格结构直接表示为图（Graph），用图神经网络（GNN）学习节点之间的信息传播规律，从而实现流场的时间步推进预测。

### 整体架构：Encoder — Processor — Decoder

```
Node features [6] ────┐                           ┌──→ Output [3]
                       ├→ [Encoder MLP] → [128] ──┤
Edge features [3] ────┘                           │   [Decoder MLP]
                                                   │
                       15 × Message Passing Block ─┘
                       (each block: Edge MLP + Node MLP)
```

**（1）输入特征**

| 特征来源 | 维度 | 内容 |
|---------|------|------|
| 节点特征 | 6 | 当前时刻速度 (u, v) × 2，节点类型 one-hot × 4 |
| 边特征 | 3 | 相邻节点坐标差 (Δx, Δy)，边长 \|Δr\| |

**（2）Encoder**

将原始节点特征（6维）和边特征（3维）分别用 MLP 映射到 128 维的隐向量空间。MLP 为 2 层，隐层宽度 128，激活函数 ReLU（默认）。

**（3）Processor（消息传递）**

核心计算模块，共 **15 个消息传递块**串联。每块内部分两步：

1. **边更新**：将当前节点特征和边特征拼接，通过 2 层 MLP（隐层 128）更新边表示。
2. **节点更新**：聚合邻居边的更新结果，与当前节点特征拼接，通过 2 层 MLP（隐层 128）更新节点表示。

经过 15 轮迭代后，每个节点的表示中融入了多跳邻域的物理信息。

**（4）Decoder**

用 2 层 MLP（隐层 128）将每个节点的 128 维隐向量映射到 3 维输出。

**（5）输出**

| 输出维度 | 含义 |
|---------|------|
| Δu, Δv | 速度增量（当前步相对上一步的变化量） |
| p | 当前步的压力值 |

预测时通过累加速度增量实现自回归展开：  
`u(t+1) = u(t) + Δu(t)`

**模型规模**

| 项目 | 数值 |
|------|------|
| 总参数量 | 2,332,419（约 233 万） |
| 模型文件大小 | ~8.9 MB |
| 消息传递层数 | 15 |
| 隐层宽度 | 128 |

## 四、可参数化部分

本数据集的一个重要特点是**每个训练样本对应不同的物理场景配置**，圆柱的几何参数和来流条件在样本间均有变化，构成参数化设计空间。模型通过在多种配置上训练，学习到跨参数的泛化能力。

### 可变参数

| 参数 | 变化范围（测试集观测值） | 如何在数据中体现 |
|------|------------------------|----------------|
| 圆柱位置（x, y） | x ∈ [0.21, 0.49] m，y ∈ [0.11, 0.23] m | `mesh_pos`：圆柱节点坐标随之变化 |
| 圆柱半径 | r ≈ 0.023 ~ 0.076 m | `mesh_pos`：圆柱附近节点密度和分布变化；圆柱周长影响壁面节点数 |
| 来流速度 / 雷诺数 | 跨样本变化（具体值隐含于速度场时序中） | `velocity`：各样本初始速度场不同 |

**这些参数不是以数值形式显式传入网络**，而是通过网格几何（节点位置、连接关系）和节点类型标签隐式编码。网络从图结构本身感知圆柱的大小和位置，无需额外参数输入。

### 在配置文件中如何指定

模型的超参数和训练参数通过 Hydra 配置文件管理：

```
conf/
├── config.yaml              # base config (batch_size, lr, feature dims, etc.)
└── experiment/
    └── full_train.yaml      # training scale overrides (epochs, num_samples, num_steps)
```

典型配置项：

```yaml
# conf/config.yaml
num_input_features: 6    # node input feature dimension
num_edge_features: 3     # edge feature dimension
num_output_features: 3   # output dimension
num_training_samples: 400
num_training_time_steps: 300
num_test_samples: 10
num_test_time_steps: 300
```

若需调整训练规模或覆盖参数，通过命令行传入即可，无需改动代码：

```bash
python train.py +experiment=full_train num_training_samples=1000
```

## 五、训练情况

### 训练配置

| 参数 | 值 |
|------|----|
| 训练样本数 | 400（共 1000 可用） |
| 每样本使用时间步 | 300（共 600 步） |
| 总训练 epoch | 35 |
| Batch size | 8 |
| 优化器 | Adam |
| 初始学习率 | 1e-4 |
| 学习率衰减 | 指数衰减，rate=0.9999991/step |
| 混合精度 | AMP（FP16） |
| 硬件 | RTX 3090（24 GB） |
| 平均 GPU 利用率 | 77.9% |

### 训练流程

训练采用两阶段策略：

**Phase 1（验证阶段，epochs 0–4）：** 先跑 5 个 epoch 确认完整训练配置（400 样本 × 300 时间步）可以正常收敛，再投入完整训练周期。Phase 1 用时约 1 小时 50 分钟，epoch 4 loss 已降至 0.0318，确认收敛正常。

**Phase 2（完整训练，epochs 4–34）：** 从 Phase 1 的权重继续训练，中间经历一次手动暂停并从 checkpoint 成功恢复。Phase 2 用时约 14 小时，平均每 epoch 约 26.5 分钟。

**总计：** 约 15 小时 50 分钟完成全部 35 个 epoch 训练。

### 损失曲线

下表列出关键 epoch 的训练 loss（均方误差，在归一化空间内计算）：

| Epoch | Loss | 较初始下降 |
|-------|------|-----------|
| 0 | 0.1259 | — |
| 5 | 0.0256 | -79.7% |
| 10 | 0.0208 | -83.5% |
| 20 | 0.0167 | -86.7% |
| 30 | 0.0146 | -88.4% |
| **34** | **0.01397** | **-88.9%** |

整体收敛平稳，无振荡，无平台期。到 epoch 34 时 loss 仍有缓降趋势，说明模型尚未完全收敛，继续训练仍有提升空间。

### 推理精度（10 个测试样本，300 步自回归展开）

| 变量 | RMSE | 相对误差 | 说明 |
|------|------|---------|------|
| u（主流方向速度） | 0.0478 | **5.6%** | 精度最高，主流速度量级大（~1 m/s） |
| v（横向速度） | 0.0409 | 22.8% | 相对误差偏大，原因是 v 的量级远小于 u（~0.1–0.2 m/s），分母小放大了比值 |
| p（压力） | 0.0561 | 17.4% | 涡后区低压涡核复杂，长程自回归误差有一定累积 |

> 注：推理采用完全闭环方式（每步以上一步模型预测作为输入），300 步连续自回归展开。相比"一步预测"，闭环推理误差会随时间步累积，是对模型长时稳定性的严格考验。v 和 p 的绝对误差（RMSE）实际上与 u 处于同一量级，相对误差偏大主要是量级差异所致，并非模型在这两个变量上表现更差。

## 六、小结

本项目基于 MeshGraphNet 完成了针对参数化圆柱绕流问题的代理模型训练。模型以非结构网格图为输入，通过 15 层消息传递实现流场状态的逐步时间推进，参数量约 233 万。在 400 个训练样本（不同圆柱位置、大小和来流条件）上训练 35 个 epoch 后，主流速度 u 的自回归推理误差达到 5.6%，整体精度满足代理模型的应用需求。
